# ۴. سرور سلامت به‌جای Express

- **وضعیت:** پذیرفته‌شده
- **تاریخ:** ۱۴۰۵

## زمینه

نسخهٔ قبلی Express داشت، به‌همراه Swagger، CORS، helmet، compression، hpp و
morgan. در عمل **هیچ روتی پیاده‌سازی نشده بود** و تنها چیزی که پاسخ می‌داد
`GET /` بود که ۲۰۰ برمی‌گرداند.

یعنی هشت وابستگی، یک لایهٔ مسیریابی و یک سطح مستندات، فقط برای نگه‌داشتن
پروسه زنده. هرکدام از این‌ها به‌روزرسانی امنیتی می‌خواهد، و Swagger یک سطح
حملهٔ اضافه است که هیچ کاربری از آن استفاده نمی‌کرد.

## تصمیم

یک سرور `node:http` بدون هیچ وابستگی، با دو مسیر:

| مسیر | نقش | پاسخ |
| --- | --- | --- |
| `GET /health` | liveness | همیشه ۲۰۰ تا وقتی پروسه بالاست |
| `GET /ready` | readiness | یک کوئری واقعی به دیتابیس؛ در خطا ۵۰۳ |

```ts
this.server = createServer((request, response) => {
  this.handle(request, response).catch(error => {
    this.respond(response, 500, { status: 'error' });
  });
});
```

تفکیک این دو عمدی است: پروسه‌ای که فایل دیتابیسش از زیر پایش حذف شده هنوز
«زنده» است ولی نمی‌تواند کار مفیدی بکند. `/ready` این را با یک کوئری واقعی
(`SELECT COUNT(*)`) تشخیص می‌دهد، نه با «هندل باز است یا نه».

## پیامدها

**مثبت**

- هشت وابستگی و کل سطح Swagger حذف شد.
- هیچ میدل‌وری برای پیکربندی و به‌روزرسانی وجود ندارد.
- `/ready` یک بررسی واقعی است، پس ارکستراتور یک کانتینر نیمه‌مرده را از
  چرخهٔ ترافیک بیرون می‌گذارد.

**منفی**

- اگر روزی API واقعی لازم شد (مثلاً وب‌هوک)، باید دستی اضافه شود. با
  `node:http` این کار چند خط است، ولی رهگیری مسیر و اعتبارسنجی بدنه را
  خودتان باید بنویسید. در آن نقطه، اضافه‌کردن یک فریم‌ورک تصمیم درستی است؛
  امروز نه.

**نکتهٔ امنیتی**

پورت فقط روی `127.0.0.1` منتشر می‌شود. این سرویس هیچ احراز هویتی ندارد و
`/ready` تعداد کاربران و نشست‌های فعال را برمی‌گرداند، که اطلاعات عملیاتی
است و نباید عمومی باشد.
