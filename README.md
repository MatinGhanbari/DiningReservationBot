# ربات رزرو غذای سلف دانشگاهی

ربات تلگرام برای رزرو ناهار از سامانهٔ سماد، با رزرو خودکار، اشتراک‌گذاری کد
فراموشی و پنل پشتیبانی.

این پروژه بازنویسی کامل نسخهٔ قبلی است: پایگاه داده از MongoDB به SQLite منتقل
شده، Redis و Express حذف شده‌اند، معماری به لایه‌های مستقل تقسیم شده و همهٔ
متن‌های کاربر بر اساس اصول نگارش فارسی بازنویسی شده‌اند.

## شروع سریع

```bash
cp .env.example .env
# BOT_TOKEN و ENCRYPTION_KEY را پر کنید
openssl rand -hex 32          # مقدار ENCRYPTION_KEY

docker compose up -d --build
docker compose logs -f bot
```

ربات باید در تلگرام پاسخ دهد. سلامت سرویس:

```bash
curl http://127.0.0.1:3000/health   # زنده بودن فرایند
curl http://127.0.0.1:3000/ready    # آماده بودن برای کار
```

## قابلیت‌ها

| قابلیت | توضیح |
| --- | --- |
| ورود به حساب | نام کاربری و رمز سماد، رمز شده با AES-256-GCM ذخیره می‌شود |
| مشاهدهٔ منو | وعده‌های قابل رزرو به تفکیک سلف و هفته |
| رزرو غذا | رزرو ناهار با تأیید، و گزارش نتیجهٔ دقیق از سماد |
| رزرو خودکار | رزرو وعده‌های روزهای دلخواه، پیش از پر شدن ظرفیت |
| کد فراموشی | دریافت کد برای وعدهٔ امروز، یا اهدای کد خودت به مخزن مشترک |
| اطلاعات من | اعتبار باقی‌مانده، نام و مشخصات حساب |
| پشتیبانی | ارسال پیام به ادمین‌ها از داخل ربات |

## معماری

معماری لایه‌ای با الگوی پورت و آداپتور. هر لایه فقط به لایهٔ زیرین خودش
وابسته است و هیچ‌جا وابستگی سراسری وجود ندارد؛ همه‌چیز در یک نقطه ساخته
می‌شود.

```
src/
├── domain/          موجودیت‌ها و پورت‌ها، بدون هیچ ورودی/خروجی
│   ├── models.ts        تایپ‌های دامنه
│   ├── ports.ts         قراردادهای ریپازیتوری و درگاه‌ها
│   └── universities.ts  فهرست دانشگاه‌ها
│
├── app/             یوزکیس‌ها، منطق کسب‌وکار
│   ├── session.service.ts       عمر توکن سماد
│   ├── auth.service.ts          ورود و خروج
│   ├── reservation.service.ts   مشاهدهٔ منو و رزرو
│   ├── forget-code.service.ts   مخزن کد فراموشی
│   └── auto-reserve.service.ts  رزرو خودکار
│
├── db/              SQLite و ریپازیتوری‌ها
├── cache/           کش درون‌حافظه‌ای (نشست، وضعیت گفتگو)
├── crypto/          رمزنگاری رمز عبور
├── samad/           کلاینت HTTP و مترجم پاسخ‌های سماد
│
├── bot/             لایهٔ نمایش (تلگرام)
│   ├── handlers/        هندلرهای هر صفحه
│   ├── keyboards.ts     کیبوردها و برچسب دکمه‌ها
│   ├── callback-data.ts کدگذاری دادهٔ دکمه‌ها
│   ├── state.ts         وضعیت گفتگو
│   └── reply.ts         ارسال پاسخ و ترجمهٔ خطا به فارسی
│
├── copy/fa.ts       تمام متن‌های کاربر، در یک فایل
├── http/health.ts   سرور سلامت
├── scheduler/       زمان‌بند
├── container.ts     ریشهٔ ترکیب، تنها جایی که وابستگی ساخته می‌شود
└── main.ts          نقطهٔ ورود و خاموشی تمیز
```

**چرا این ساختار:** هر لایه را می‌توان جدا آزمود. `ForgetCodeService` برای
تست‌شدن به تلگرام، شبکه یا دیتابیس واقعی نیاز ندارد؛ همان چیزی که در نسخهٔ
قبلی ناممکن بود، چون سرویس‌ها همدیگر را داخل سازندهٔ خودشان می‌ساختند و
`AuthService` و `UserService` یک حلقهٔ وابستگی ساخته بودند.

### جریان یک درخواست

```
پیام تلگرام
  → bot/handlers        تشخیص صفحه و اعتبارسنجی ورودی
  → app/*.service       تصمیم کسب‌وکار
  → app/session.service توکن تازه یا از کش
  → samad/gateway       ترجمهٔ دامنه ↔ سماد
  → samad/client        HTTP با مهلت و تلاش مجدد
```

## توسعهٔ محلی

نیازمند Node نسخهٔ ۲۲ یا بالاتر.

```bash
npm ci
cp .env.example .env

npm run dev          # اجرا با بارگذاری خودکار
npm run typecheck    # بررسی تایپ‌ها
npm test             # آزمون‌ها
npm run lint         # ESLint
npm run format       # Prettier
```

برای اجرای محلی، `DATABASE_PATH` را روی یک مسیر محلی بگذارید (پیش‌فرض
`./data/bot.db`) و `LOG_PRETTY=true` را برای لاگ خوانا روشن کنید.

## متغیرهای محیطی

همهٔ متغیرها در `.env.example` با توضیح فارسی آمده‌اند. اجباری‌ها:

| متغیر | پیش‌فرض | توضیح |
| --- | --- | --- |
| `BOT_TOKEN` | — | **اجباری.** توکن ربات از BotFather |
| `ENCRYPTION_KEY` | — | **اجباری.** حداقل ۳۲ کاراکتر برای رمزنگاری رمز کاربران |
| `ADMINS` | `[]` | آرایهٔ JSON از شناسهٔ عددی ادمین‌ها |
| `DATABASE_PATH` | `./data/bot.db` | مسیر فایل SQLite |
| `AUTO_RESERVE_CRON` | `0 7 * * *` | زمان اجرای روزانهٔ رزرو خودکار |
| `TZ` | `Asia/Tehran` | منطقهٔ زمانی فرایند |
| `RESERVABLE_DAYS_AHEAD` | `2` | چند روز جلوتر یک وعده قابل رزرو می‌شود |
| `PORT` | `3000` | پورت سرور سلامت |
| `LOG_LEVEL` | `info` | `fatal` تا `trace` |
| `DB_CACHE_MB` | `64` | کش صفحه‌های SQLite در حافظه |
| `DB_MMAP_MB` | `256` | نگاشت حافظه‌ای فایل دیتابیس |
| `SESSION_TTL_MINUTES` | `60` | عمر نشست در حافظه |
| `SAMAD_TIMEOUT_MS` | `15000` | مهلت هر درخواست به سماد |
| `SAMAD_MAX_RETRIES` | `2` | تلاش مجدد در خطای گذرا |

> **هشدار:** با تغییر `ENCRYPTION_KEY` رمزهای ذخیره‌شدهٔ قبلی قابل خواندن
> نیستند و همهٔ کاربران باید دوباره وارد شوند.

## بهره‌برداری

### سلامت سرویس

| مسیر | معنا |
| --- | --- |
| `GET /health` | زنده بودن فرایند. همیشه ۲۰۰ تا وقتی که پروسه بالاست |
| `GET /ready` | آماده بودن. یک کوئری واقعی به دیتابیس می‌زند و در صورت خطا ۵۰۳ می‌دهد |

تفاوت این دو مهم است: فرایندی که دیتابیسش از زیر پایش حذف شده هنوز «زنده»
است ولی نمی‌تواند کار مفیدی بکند.

پورت فقط روی `127.0.0.1` باز می‌شود، چون این سرویس هیچ احراز هویتی ندارد و
بازکردنش روی `0.0.0.0` تعداد کاربران و نشست‌های فعال را برای همه قابل خواندن
می‌کند.

### لاگ‌ها

لاگ‌ها ساخت‌یافته (JSON) و روی stdout هستند. رمز عبور، توکن و هدر
`authorization` به‌صورت متمرکز حذف می‌شوند و هرگز در لاگ نمی‌آیند.

```bash
docker compose logs -f bot
docker compose logs bot | grep '"level":50'    # فقط خطاها
```

### به‌روزرسانی

```bash
git pull
docker compose up -d --build
```

مهاجرت‌های دیتابیس هنگام بالا آمدن و به‌صورت خودکار اجرا می‌شوند. هر مهاجرت
در یک تراکنش با شمارهٔ نسخه‌اش انجام می‌شود، پس یک مهاجرت نیمه‌کاره باقی
نمی‌ماند.

### بازگشت به عقب

```bash
git checkout <commit>
docker compose up -d --build
```

مهاجرت‌ها فقط به جلو می‌روند و حذف‌کننده نیستند، پس اسکیمای جدید با کد قدیمی
هم سازگار است.

### خاموشی

کانتینر در `SIGTERM` تا ۸ ثانیه فرصت دارد: زمان‌بند می‌ایستد، ربات و سرور
سلامت بسته می‌شوند و پیش از بسته‌شدن دیتابیس یک checkpoint نهایی WAL اجرا
می‌شود تا راه‌اندازی بعدی مجبور به بازپخش لاگ نباشد.

## پشتیبان‌گیری

دیتابیس SQLite است، پس پشتیبان‌گیری یعنی کپی یک فایل، ولی کپی ساده وقتی
WAL فعال است می‌تواند ناسازگار باشد. از `VACUUM INTO` استفاده کنید که یک
نسخهٔ سازگار و فشرده می‌سازد:

```bash
docker compose exec bot node -e "
  const Database = require('better-sqlite3');
  const db = new Database(process.env.DATABASE_PATH, { readonly: true });
  db.exec(\"VACUUM INTO '/app/data/backup.db'\");
  db.close();
"
docker compose cp bot:/app/data/backup.db ./backup-$(date +%F).db
```

نسخهٔ سازگار را می‌توان در حال اجرا هم گرفت، چون `VACUUM INTO` فقط خواندن
می‌کند. والیوم `bot-data` را هم می‌توان مستقیماً پشتیبان گرفت، ولی برای
بازگرداندن، کانتینر باید متوقف باشد.

## کیفیت کد

```bash
npm run typecheck    # بدون خطا
npm test             # ۱۳۶ آزمون
npm run lint
```

آزمون‌ها روی Vitest هستند و هر آزمون دیتابیس درون‌حافظهٔ خودش را می‌سازد، پس
هیچ آزمونی روی دیگری اثر نمی‌گذارد. زمان و شبکه هر دو شبیه‌سازی شده‌اند:
هیچ آزمونی به سماد یا تلگرام وصل نمی‌شود.

پوشش: رمزنگاری، مهاجرت و ریپازیتوری‌ها، ترجمهٔ پاسخ‌های سماد، عمر توکن،
رزرو خودکار، مخزن کد فراموشی، متن‌های فارسی، سرور سلامت و کدگذاری دادهٔ
دکمه‌ها.
